# 桌面收纳工具调研与开发说明

调研日期：2026-10-31。以下选择的是这一类产品的代表，按功能适配程度比较；没有把厂商宣传或网页出现频率当作下载量排名。

## 值得借鉴的产品

| 产品 | 官方公开能力与优点 | 对 Foldergrid 的启发 |
| --- | --- | --- |
| [Stardock Fences 6](https://www.stardock.com/products/fences/) | 桌面分区、按类型/名称/时间的自动规则、文件夹入口、Peek 快捷呼出、标签页与外观定制 | 高频操作无需返回桌面，按用户习惯组织文件；先做规则和呼出 |
| [Portals](https://portals-app.com/) | 映射真实文件夹，标签页、排序、逐个入口的外观设置；保存布局并随显示器配置切换 | 映射不要求搬文件；后续值得做多屏布局、标签合并 |
| [iTop Easy Desktop](https://www.itopsoftware.com/user-manual/ied/) | 自动分区、自定义规则、Folder Portal、搜索、布局快照、标签合并；另有壁纸和小组件 | 把搜索和分类做成容易找到的入口，减少首次使用成本 |
| [腾讯桌面整理](https://guanjia.qq.com/product/zmzl/) | 桌面文件分类、磁盘映射、全盘搜索和壁纸 | 中文用户习惯通过“分类 + 映射 + 搜索”找文件 |
| [小智桌面](https://todobing.cqttech.com/xzdesk/) | 一键整理、后缀/关键词规则、文件夹映射、分区合并、收起、布局备份还原 | 规则可理解、可调整；未来增加布局恢复和分区合并 |

Fences 与 Portals 的能力集中在文件组织和访问效率，较适合作为本项目的产品参考。壁纸、天气、AI 助手等会引入额外依赖或在线服务，本批以本地文件收纳为范围。

## v0.3.0 基础能力

已阅读主进程、渲染层、preload、Win32 桌面适配、Explorer 目标识别、存储与预览模块及测试。项目为 Electron 45.1.0、electron-builder 26.18.0、Koffi 3.3.5；无需改成 macOS 技术栈。已有真实文件夹格子、透明桌面窗口、托盘、文件移动、文本预览、自由布局、回收站和外观设置。

用户上传的 v0.3.0 是最终基线，不能用 GitHub main 中版本较旧的文件覆盖这些已有功能。

## 本批实现

| 能力 | 实现范围 | 边界 |
| --- | --- | --- |
| 跨格子搜索 | 名称/格子名、多关键词、最近修改优先、键盘选择、打开与定位 | 搜索第一层，最多显示 200 条；不是全盘索引 |
| 排序与筛选 | 自由摆放、名称、最近修改、类型、大小；文件类型过滤；每格子保存排序 | 搜索/筛选视图临时规整展示，原自由坐标保留 |
| 外部文件夹映射 | 目录选择器授权、原位浏览、预览、打开、第一层变化监听、移除映射 | 映射中不修改原文件；断盘提示并支持刷新 |
| 分类规则 | 后缀、关键词、启停、顺序编辑；默认六类；手动预览后原生确认 | 桌面第一层普通文件，一次最多 1000 项，不持续自动搬运 |
| 撤销 | 每次移动写入持久记录；可逐次撤销；检查修改/替换/重名 | 已修改文件跳过；异常退出的 pending 项需检查日志后手动处理 |
| 快捷访问 | 呼出/收回、搜索、隐藏/显示、占用检测 | 需 Windows 实机确认桌面归属和快捷键组合表现 |

关键改动：`src/workspace.js` 隔离分类和撤销逻辑，`src/main.js` 接入 IPC、映射和快捷键；`media/file-view.js` 复用排序筛选，`media/workspace-ui.js` 与 CSS 提供工作台界面。已有 IPC 来源校验、渲染沙箱、文件路径边界保留。映射的真实路径校验阻止通过符号链接访问授权目录外内容。

## 下一批建议

1. **多屏与 DPI 布局快照**：优先解决笔记本接显示器、分辨率切换后的布局恢复。需要 Windows 实机覆盖显示器拓扑。
2. **格子标签合并**：多个目录在同一卡片切换，减少桌面占用。
3. **可选持续分类**：先补充后台任务队列、操作日志和失败重试，再由用户主动启用。
4. **更完整预览**：PDF 和图片预览可独立迭代，避免阻塞整理主流程。

这些是后续建议，本次没有把尚未实现的功能放进操作界面。
